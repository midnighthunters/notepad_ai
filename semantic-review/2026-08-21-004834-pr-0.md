# Snapshot-bound native AI editing core

This change adds a UI-free pipeline that resolves an editing scope, gives a provider a bounded prompt, parses a snapshot-bound edit plan, previews it, and applies descending operations inside an undo action. The parser derives per-range hashes from the authoritative snapshot and requires an allowed scope, preventing model output from supplying its own range proof. Provider adapters, a Windows credential store, and WinHTTP establish the network boundary without making live requests. Watch for: **confirmed** cancellation can still dispatch a callback after `cancel()` returns; **likely** a same-text different-document target and a truncated prompt's omitted bytes are not bound tightly enough; **confirmed** credential-bearing adapters can use the loopback HTTP exception.  
**Verdict**: NEEDS_CHANGES

## High-level view

The core’s content binding stops at the text hash: **likely** `documentIdentity` and `revision` are carried in the snapshot yet never reach the editor contract used at application time. A switched document with identical bytes cannot be distinguished by this core.

The prompt separates trusted request metadata from untrusted document data and includes the authorized absolute range. When bounded context is truncated, **likely** the model receives no exact byte map for the retained suffix or omitted interval while the full original scope remains authorized, so a valid-looking operation can target text it never received.

**Confirmed:** the generic transport permits plaintext loopback endpoints for every provider, so a configuration can send an OpenAI, Azure, Anthropic, or Gemini secret to a local HTTP service as well as to secretless Ollama.

The request manager’s automatic reaper owns completed worker lifetimes, but **confirmed** cancellation is not synchronized with the final callback handoff. Cancellation can win after the worker’s final checks and still be followed by callback execution.

<summary>Issues (5)</summary>

1. **Cancellation callback race (confirmed)** — `cancel()` can return before a worker invokes a callback that passed its last cancellation check. Synchronize cancellation and callback ownership, then add a deterministic handoff-race test.
2. **Unbound document identity (likely)** — application verifies only current text and hash, not the snapshot’s identity or revision. Bind `IAiEditor` to an identity/revision or require a verified snapshot token before the undo action starts.
3. **Truncated-context write gap (likely)** — the model has no absolute map for omitted and suffix data but may propose operations across the entire original scope. Include transmitted segment ranges and reject edits outside them, or fail closed on truncation.
4. **Secrets may use plaintext loopback HTTP (confirmed)** — every credentialed adapter inherits the local HTTP exception. Require HTTPS for secret-bearing adapters or make this a named, explicit local-service opt-in.
5. **Native validation unexecuted (confirmed)** — CMake, CTest, `cl`, and `g++` are unavailable in this workspace. Compile and run the offline target, including Windows WinHTTP coverage, in a provisioned environment.

## Cancellation can race past the callback gate

**Confirmed:** `AiRequestManager::cancel` sets `RequestState::cancelled` and requests stop without taking `dispatchMutex`. The worker checks that flag, takes `dispatchMutex`, checks it again, and then calls the completion callback; cancellation can set the flag and return in the interval after that second check but before the callback invocation. The public contract says cancellation suppresses callbacks that have not started dispatching, so this interleaving violates the contract and can update a UI or apply a result after a caller believes the request is cancelled.

```
worker: observes cancelled == false and passes final check
cancel: sets cancelled = true, requests stop, returns true
worker: invokes callback
```

Make cancellation and callback ownership a single synchronized handoff, with an explicit callback-start state. **Confirmed test gap:** the deterministic test cancels a blocked provider before it completes; it needs a fixture that pauses immediately after the final cancellation check and proves no callback begins after `cancel()` returns.

## Snapshot identity is not part of application validation

**Likely:** `AiDocumentSnapshot` stores `documentIdentity` and `revision`, but `IAiEditor` exposes only `captureText`, and `AiEditApplier::apply` accepts an editor when its current bytes and SHA-256 equal the snapshot. The core therefore cannot reject applying a response to a different editor document with identical contents, such as two tabs created from the same template after focus changes. The byte hash protects textual staleness but not target-document identity.

Bind the editor capture to a document identity and revision, or make the integration present a snapshot token that the applier verifies immediately before opening the undo action. If identical text in a different document is deliberately permitted, remove the unused identity/revision fields or state that ownership must be enforced outside this API.

## Truncated document context has no exact range map

**Likely:** `AiBuildEditPrompt` emits the complete `authorized_byte_range` even when `boundedContext` replaces the middle of the scope with an omission marker. The generated user message does not state the byte interval omitted or the absolute start of the retained suffix; `AiPrompt::omittedContextBytes` is returned only to native callers. `AiParseAndValidateEditPlan` then accepts any operation inside the whole scope and derives its expected hash locally, including an operation against omitted text.

Include trusted segment metadata for every transmitted document fragment and restrict model-originated operations to those fragments, or fail closed when a requested edit needs context that was omitted. That preserves the bounded-data policy without turning an unobserved portion of the document into a writable target.

## Loopback HTTP is available to secret-bearing providers

**Confirmed:** the endpoint validator permits `http://localhost`, `http://127.0.0.1`, and `http://[::1]` for every `AiHttpRequest`; `AiHttpProvider` serializes authorization headers before handing requests to that generic transport. Consequently a cloud-provider credential is sent in cleartext to any configured local listener, not only to the secretless Ollama adapter. This may be intentional for local OpenAI-compatible services, but it needs an explicit trust decision rather than inheriting the Ollama development exception.

Require HTTPS whenever an adapter requires a secret, or add a provider configuration flag whose opt-in name and UI copy make clear that the stored credential will be sent to a local HTTP process.

## Native validation remains unexecuted

**Confirmed:** CMake, CTest, `cl`, and `g++` are absent from `PATH`, so the standalone target has not been configured, compiled, or run in this workspace. Not tested: the C++20 build, provider fixture execution, WinHTTP compilation on Windows, the background reaper’s cleanup behavior, and the cancellation handoff race above.
