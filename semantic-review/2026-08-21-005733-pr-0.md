# Native AI editing core

The new UI-free core carries a hash-bound document snapshot and exact visible authorization range through prompt construction, plan validation, diffing, and application. Provider adapters add protected-secret handling and a WinHTTP transport with a credentialed-HTTP gate; truncated prompts narrow the range that model output may change. **Confirmed**, the offline assertion helper cannot accept `AiResult` values, so the test executable cannot compile. **Likely**, a request can escape cooperative cancellation while its worker is being published. Watch for: **confirmed** offline-test compilation failure; **likely** cancellation can fail to reach a provider during concurrent startup; **confirmed** the insecure-loopback opt-in and callback-commit contracts lack deterministic regression coverage.

**Verdict**: NEEDS_CHANGES

## High-level view

The hash-bound prompt/apply pipeline fails closed when context is truncated, but **confirmed**, its standalone build gate is blocked by direct `AiResult` assertions that require an implicit Boolean conversion the type deliberately does not provide.

The callback handoff is mutex-protected, but **likely**, startup is not: publishing a `RequestState` before assigning its `std::jthread` lets a concurrent `cancelAll()` mark cancellation without stopping the provider’s new worker.

Credentialed HTTP is false by default and limited to loopback only when explicitly enabled. **Confirmed**, fixtures cover only default rejection, not the opt-in send path or the boundary where callback dispatch has committed and `cancel()` must return false.

<summary>Details</summary>

### Offline assertions cannot consume `AiResult` values (confirmed)

`AiResult<T>` exposes `explicit operator bool()`, while the test macro expands direct assertions into `require(bool, ...)`. Function-argument conversion to `bool` is not a contextual Boolean conversion, so `REQUIRE(test, parsed)` and `REQUIRE(test, prompt)` in `PowerEditor/Test/AI/AiCoreTests.cpp` cannot bind their `AiResult` argument to the helper. **Confirmed**, the standalone target fails before it can exercise the advertised behavior. Convert the assertion expression explicitly in the macro or have the helper accept an expression type and perform a contextual Boolean conversion internally.

### Request publication leaves a cancellation window (likely)

`AiRequestManager::start` inserts the `RequestState` into `_requests` before assigning `state->worker`. **Likely**, a concurrent `cancelAll()` can mark that state cancelled and call `request_stop()` on the default `std::jthread`; the later worker receives an unrequested stop token and may run a live provider request to completion. Callback suppression still occurs after the provider returns, but cancellation no longer reaches the transport, and assignment and `request_stop()` are not coordinated. Publish the state only after the worker is ready, or synchronize startup with cancellation and request stop immediately after assignment when cancellation won the race.

### Credentialed-loopback and callback-commit behavior lack fixtures (confirmed)

`testEndpointSecretsAndCancellation` proves that a credentialed provider rejects loopback HTTP when `allowInsecureLoopbackForSecret` is false, but it never enables the override and asserts that the fake transport receives the resulting request. **Confirmed**, it also tests cancellation before the provider completes rather than the documented boundary where callback dispatch has committed and `cancel()` must return false. Add deterministic fixtures for both branches; they are the regression coverage for the new transport-trust and cancellation contracts.

### Native execution is still unverified (confirmed)

Not tested: native configure, compile, and CTest. **Confirmed**, `cmake`, `ctest`, `cl`, `clang++`, `g++`, and `c++` are absent from `PATH`; the compile finding above is static and needs native-build confirmation after the assertion helper is repaired.

</details>
