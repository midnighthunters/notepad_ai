# Native AI editing core and offline test harness

This change introduces a UI-free C++20 AI editing pipeline: it resolves a document scope, frames a prompt, decodes provider output into a hash-bound edit plan, and applies that plan through an undo-aware editor abstraction. It also adds provider adapters, a Credential Manager-backed secret store, a WinHTTP transport, and an offline CMake test executable. The boundary between resolved scope, prompt, and validated plan is incomplete, so the safety checks cannot reliably authorize the change the model proposes. **Watch for:** **confirmed** the prompt omits the document/range hash values and absolute coordinates that its own validator requires; **confirmed** selection and line-range scope are never enforced at validation or apply time; **likely** deeply nested model JSON can exhaust the validation walk before schema rejection.

**Verdict**: NEEDS_CHANGES

## High-level view

**confirmed** The prompt sends bounded document context while demanding document-relative byte offsets and SHA-256 values that it never supplies. The resulting protocol lacks the information needed to construct a plan that the core will accept.

**confirmed** Scope resolution determines which text enters the prompt, but no downstream API carries an allowed range. A selection or line range therefore acts as advisory context rather than a boundary on mutations.

**confirmed** A post-preflight editor failure can expose a partial undo group. **likely** deeply nested JSON can exhaust the recursive UTF-8 validation walk, while completed request state is retained until a caller explicitly reaps it.

<details>
<summary>Issues (6)</summary>

1. **Prompt contract lacks snapshot metadata (confirmed)** — `AiBuildEditPrompt` requires document and expected-range SHA-256 values plus document-relative byte ranges but never supplies the snapshot hash, scope offset, or range hashes. Include authoritative snapshot/range metadata or change the protocol so the core derives expected hashes after validating model-proposed ranges.
2. **Resolved scope is not enforced (confirmed)** — plans are validated and applied against the entire snapshot, not the selection or line range used to build the prompt. Pass an allowed `AiScope` into validation/application and reject any operation outside it, including empty insertions at its boundaries.
3. **Apply can leave partial edits after begin (confirmed)** — a failing `replaceRange` ends the undo group but does not roll back earlier replacements. Add an abort/rollback contract, or explicitly make failure after successful preflight impossible, and test that path.
4. **JSON nesting is unbounded (likely)** — a 512 KiB response can still contain hundreds of thousands of nested arrays or objects, and `validateJsonUtf8` recursively traverses it before structural rejection. Enforce a nesting limit with a streaming/depth-aware parser and add an adversarial fixture.
5. **Completed request handles rely on callers to reap (confirmed)** — finished `std::jthread` states remain in `_requests` until `reapCompleted()` is called or a later `start()` happens. Arrange automatic completion cleanup or make a manager-owned completion drain mandatory.
6. **Credential target names can be truncated at an embedded NUL (confirmed)** — validation accepts a `wstring_view` containing `L'\0'`, but Win32 APIs receive a null-terminated string. Reject embedded NULs before `CredWriteW`, `CredReadW`, or `CredDeleteW`.

</details>

<summary>Details</summary>

### Prompt contract cannot produce hash-bound, document-relative edits

**confirmed** — `AiBuildEditPrompt` tells the model to include the document SHA-256 and every original-range SHA-256 at `PowerEditor/src/AI/AiCore.cpp:581-589`, then sends only the user instruction and raw context at `:584-601`. It never interpolates `snapshot.documentSha256`, a document length, `scope.range.start`, or `scope.range.end`. `AiValidateEditPlan` subsequently requires an exact document hash and exact hash for every range at `:684-735`.

**likely** a model receiving a selection or line-range excerpt will return positions relative to that excerpt and cannot reliably calculate SHA-256 values for arbitrary ranges. The validator will reject such a response, but only after a provider call. The test constructs correct hashes directly in C++ at `PowerEditor/Test/AI/AiCoreTests.cpp:241-263`, so it does not exercise the prompt-to-plan contract.

The prompt needs to state the authoritative document hash and absolute scope bounds. The protocol also needs a realistic way to bind proposed ranges to source text: the core can derive `expected_hash` after checking each proposed range against the captured snapshot, or the model needs a trusted hash/range capability rather than being asked to calculate cryptographic digests.

### Selection and line-range scope disappear before apply

**confirmed** — `AiResolveScope` returns a range at `PowerEditor/src/AI/AiCore.cpp:375-401`, and `AiBuildEditPrompt` slices context from it at `:596`. `AiParseAndValidateEditPlan`, `AiValidateEditPlan`, `AiBuildDiffModel`, and `AiEditApplier::apply` take only a plan and snapshot at `:610-795`; none receives an `AiScope` or tests whether an operation is contained in one.

Any hash-valid plan for the snapshot can therefore alter unrelated text, despite a narrow selection or line range having been resolved. **confirmed** the document hash prevents edits against a changed document, not edits outside the requested scope. This is a trust-boundary gap: a faulty or hostile provider can expand a narrow request into a whole-document mutation. Containment must include zero-length insertions so an insertion immediately outside a selected range cannot pass through a boundary convention.

### Replace failure is not atomic once the undo action opens

**confirmed** — every operation is preflighted before `beginUndoAction()` at `PowerEditor/src/AI/AiCore.cpp:780-789`, but the loop at `:791-795` returns as soon as a later `replaceRange` fails. `UndoActionGuard` only calls `endUndoAction()` at `:293-303`; it has no rollback capability. Any already-applied higher-offset edits remain in the editor even though `apply()` reports failure.

The interface comment asks an editor to guarantee a successful `CanReplaceRange` means `ReplaceRange` will complete, but the error branch remains public and untested. A one-step undo can make the partial result reversible for some editors; it does not make the failed API call atomic.

### JSON schema validation has no nesting boundary

**likely** — the raw-response limit at `PowerEditor/src/AI/AiCore.cpp:610-613` limits bytes but not structural depth. The parser materializes the entire JSON value at `:621`, then `validateJsonUtf8` recursively descends arrays and objects at `:192-221` before the schema check. A small deeply nested payload therefore reaches a recursive walk before it can be rejected as the wrong root shape.

A depth-limited SAX pass that validates UTF-8 and keys before DOM construction would preserve strictness without exposing the UI process to stack exhaustion or disproportionate allocation.

### Completed request state is retained after callbacks finish

**confirmed** — workers set `RequestState::done` at `PowerEditor/src/AI/AiProvider.cpp:613`, but the state remains in `_requests` until `reapCompleted()` erases it at `:653-671`. The only automatic call is at the beginning of a later `start()` at `:572`; a completed batch in an otherwise idle manager keeps its `std::jthread` handles and per-request state.

The offline cancellation test calls `reapCompleted()` explicitly at `PowerEditor/Test/AI/AiCoreTests.cpp:423`, so it does not establish cleanup without client cooperation.

### Credential target names are not safe C strings

**confirmed** — `validateSecretArguments` only checks empty/length at `PowerEditor/src/AI/AiSecretStore.cpp:33-42`. Each operation constructs a `std::wstring` from the full view and passes `target.data()` or `target.c_str()` to null-terminated Win32 Credential Manager APIs at `:53-61`, `:75-79`, and `:104-107`.

An embedded `L'\0'` is accepted by the core but truncates the target name at the API boundary, allowing two distinct API inputs to alias the same stored credential.

### Offline coverage misses the new boundary failures

**confirmed** — the suite covers basic scope precedence, parser rejection, normal descending application, provider fixtures, and cancellation. **Not tested:** prompt emission of the authoritative document hash/absolute scope coordinates, out-of-scope but hash-valid operations, a `replaceRange` failure after a successful preflight, and deeply nested JSON. No native CMake build or test run was possible in this workspace because `cmake`, `ctest`, and C++ compilers are absent; only Ninja 1.13.0 is available.
